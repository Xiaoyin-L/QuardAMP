# FreeRTOS 迁移到 hart7 的阶段性进展

本文记录当前将 FreeRTOS 适配到 QuardAMP `trusted-domain` / `hart7` 的进展、关键操作、遇到的问题与解决方式，以及后续计划。

## 当前结论

FreeRTOS 已经可以在 `hart7` 上启动，并通过 `uart2` 输出任务调度日志。

当前启动链路为：

```text
pflash fw.bin
  -> lowlevelboot
  -> OpenSBI @ 0x80000000
  -> untrusted-domain: hart0-hart6 -> xv6 @ 0x82000000, S-mode
  -> trusted-domain:   hart7       -> FreeRTOS @ 0xb0000000, S-mode
```

当前串口输出：

```text
serial2 console
Hello FreeRTOS!
uTaskCreate
task2 0x0x0
task1 0x0x0
task20x0x1
task1 0x0x1
task2 0x0x2
task1 0x0x2
...
```

这说明以下链路已经打通：

- OpenSBI 可以把 `trusted-domain` 启动到 `hart7`。
- FreeRTOS 可以在 `hart7` 上运行。
- S-mode trap/timer 路径已经工作，`vTaskDelay()` 能触发任务切换。
- `task1` / `task2` 可以按 tick 周期交替运行。
- `uart2` polling 输出正常。

## 参考依据

当前适配参考了 Quard Star 教程中的 `trusted_domain` FreeRTOS 章节：

```text
https://quard-star-tutorial.readthedocs.io/zh-cn/latest/ch21.html
https://github.com/QQxiaoming/quard_star_tutorial/tree/main/trusted_domain
```

参考思路：

- FreeRTOS 不跑 M-mode，而是跑 OpenSBI 后面的 S-mode。
- tick 不直接写 `mtimecmp`，而是通过 SBI `set_timer`。
- trap 使用 S-mode CSR：`sstatus`、`sie`、`sip`、`stvec`、`scause`、`sepc`、`stval`。
- `portable/` 中只保留 `MemMang/heap_4.c`，RISC-V port 后续作为本项目自己的 port 放回 `portable/GCC/RISC-V/`。

## 已完成进展

### 1. FreeRTOS 源码整理

已将 FreeRTOS 内核源码整理到：

```text
trusted_domain/FreeRTOS-Kernel
```

`portable/` 当前只保留：

```text
trusted_domain/FreeRTOS-Kernel/portable/MemMang/heap_4.c
trusted_domain/FreeRTOS-Kernel/portable/GCC/RISC-V/port.c
trusted_domain/FreeRTOS-Kernel/portable/GCC/RISC-V/portASM.S
trusted_domain/FreeRTOS-Kernel/portable/GCC/RISC-V/portmacro.h
```

其中：

- `MemMang/heap_4.c` 是 FreeRTOS heap 实现。
- `GCC/RISC-V/` 是当前为 QuardAMP S-mode 环境使用的 RISC-V port。

### 2. trusted_domain 构建系统

新增并使用：

```text
trusted_domain/Makefile
```

`build.sh` 中 trusted_domain 的构建方式已从只编译 `startup.s` 改成调用 `trusted_domain/Makefile`：

```sh
cd $SHELL_FOLDER/trusted_domain
make clean
make CROSS_COMPILE=$CROSS_PREFIX-
```

这样会同时编译：

- FreeRTOS kernel 源码
- `portable/GCC/RISC-V` port
- `heap_4.c`
- `startup.S`
- SBI 封装
- UART/debug 输出
- 最小 stubs

### 3. 启动文件

启动文件从：

```text
trusted_domain/startup.s
```

调整为：

```text
trusted_domain/startup.S
```

原因是当前 Makefile 收集的是 `*.S` 文件。

`startup.S` 当前负责：

- 只让 `PRIM_HART = 7` 继续运行，其他 hart 进入 `wfi`。
- 清 `sie` / `sip`。
- 初始化 `gp`。
- 设置栈 `_sp`。
- 初始化 `sscratch`。
- 拷贝 `.data`。
- 清空 `.bss`。
- 调用 `main()`。

### 4. 链接地址修正

`trusted_domain/link.lds` 已修正为当前 QuardAMP 使用的地址：

```text
0xb0000000
```

这必须和以下配置一致：

- `dts/quard_star_sbi.dts` 中 trusted-domain 的 `next-addr = 0xb0000000`
- `lowlevelboot/startup.s` 中把 `trusted_fw.bin` 拷贝到 `0xb0000000`
- `build.sh` 中把 `trusted_fw.bin` 写入 `fw.bin` 的 `seek=4K`

已验证 ELF 入口：

```text
Entry point address: 0xb0000000
```

### 5. RISC-V / SBI / UART 最小平台层

新增：

```text
trusted_domain/riscv/riscv_encoding.h
trusted_domain/riscv/riscv_asm.h
trusted_domain/riscv/sbi.c
trusted_domain/riscv/sbi.h
trusted_domain/driver/quard_star.h
trusted_domain/driver/ns16550.c
trusted_domain/driver/ns16550.h
trusted_domain/driver/debug_log.c
trusted_domain/driver/debug_log.h
trusted_domain/stubs/syscalls.c
```

作用：

- `riscv_encoding.h`：提供 S-mode CSR 编号和 bit 定义。
- `riscv_asm.h`：提供 `LOAD` / `STOR` / `REGSIZE` 和 `csr_set()` 等宏。
- `sbi.c`：封装 `sbi_set_timer()`、`sbi_send_ipi()`、`sbi_clear_ipi()`。
- `quard_star.h`：记录 hart、UART、CLINT、PLIC 等板级常量。
- `ns16550.c`：实现 `uart2` polling 输出。
- `debug_log.c`：提供最小格式化日志。
- `syscalls.c`：提供裸机链接需要的最小 stub。

## 关键问题与解决

### 问题 1：`riscv_encoding.h` 找不到

报错：

```text
startup.s:1:10: fatal error: riscv_encoding.h: No such file or directory
```

原因：

教程中的 `startup.s` / `portASM.S` 依赖 `riscv_encoding.h`，但本地还没有把 `riscv/` 平台头文件落地。

解决：

新增：

```text
trusted_domain/riscv/riscv_encoding.h
trusted_domain/riscv/riscv_asm.h
```

并让 `startup.S` 包含：

```c
#include "riscv_asm.h"
```

### 问题 2：RISC-V port 放错目录

一开始 `port.c` / `portASM.S` / `portmacro.h` 误放在：

```text
trusted_domain/FreeRTOS-Kernel/portable/MemMang/GCC/RISC-V
```

这是错误的。`MemMang` 下只应该放 heap 实现。

解决：

移动到：

```text
trusted_domain/FreeRTOS-Kernel/portable/GCC/RISC-V
```

### 问题 3：Makefile 没有编译启动文件

原因：

Makefile 只收集：

```make
*.S
```

但启动文件原名是：

```text
startup.s
```

解决：

重命名为：

```text
startup.S
```

### 问题 4：RV64 被 portmacro.h 拦住

报错原因：

`portmacro.h` 中残留：

```c
#error This is the RV32 port that has not yet been adapted for 64.
```

但当前目标是 `rv64imafdc/lp64d`。

解决：

去掉该 `#error`，保留 RV64 的 16 字节对齐设置。

### 问题 5：CSR 宏没有展开

报错：

```text
unknown CSR `CSR_SIE'
```

原因：

`csr_set(CSR_SIE, ...)` 中 `CSR_SIE` 被字符串化为字面量，没有展开成 `0x104`。

解决：

在 `riscv_asm.h` 中增加二级宏展开。

### 问题 6：stack protector 链接失败

报错：

```text
undefined reference to `__stack_chk_guard'
undefined reference to `__stack_chk_fail'
```

原因：

当前使用 Linux 交叉工具链，默认可能启用 stack protector；裸机 `-nostdlib` 环境没有这些符号。

解决：

Makefile 中增加：

```make
-fno-stack-protector
```

### 问题 7：链接地址不匹配

问题：

教程链接脚本地址和当前 QuardAMP 本地加载地址不一致，曾出现 ELF entry 为：

```text
0xbf800000
```

但本项目 trusted-domain 应该从：

```text
0xb0000000
```

启动。

解决：

重写 `trusted_domain/link.lds`，将入口和镜像基地址固定为：

```text
0xb0000000
```

### 问题 8：串口输出格式有小瑕疵

当前输出：

```text
task2 0x0x0
task1 0x0x0
```

原因：

调用侧写了：

```c
debug_log("task1 0x%x\n", time++);
```

而 `debug_log()` 的 `%x` 实现内部也会输出 `0x` 前缀，所以出现 `0x0x0`。

解决建议：

将调用侧改为：

```c
debug_log("task1 %x\n", time++);
debug_log("task2 %x\n", time++);
```

或者去掉 `debug_puthex()` 内部的 `0x` 前缀。

## 当前仍需注意

### 1. uart2 目前是 polling

当前 `uart2` 输出是 polling，不依赖 PLIC 外部中断。

这很好，因为可以先验证：

- FreeRTOS 启动
- SBI timer
- task switch

后续再单独接 PLIC 外部中断。

### 2. PLIC 还没有真正接入 FreeRTOS

当前 FreeRTOS 的 timer tick 已经工作，但外部中断路径还没有验证。

下一步需要：

- 给 trusted-domain 增加 PLIC MMIO region。
- 在 FreeRTOS 中配置 hart7 的 S-mode PLIC context。
- 只启用 hart7 需要的中断源。

hart7 S-mode PLIC context 地址为：

```text
PLIC base        = 0x0c000000
hart7 SENABLE    = 0x0c002780
hart7 SPRIORITY  = 0x0c20f000
hart7 SCLAIM     = 0x0c20f004
```

### 3. UART IRQ 需要确认

当前 DTS 中 uart0/uart1/uart2 曾都写过 IRQ 10，后续要避免 xv6 和 FreeRTOS 抢同一个 PLIC source。

建议目标：

```text
uart0 -> xv6  -> IRQ 10
uart2 -> RTOS -> IRQ 12
virtio -> xv6 -> IRQ 1
```

如果 QEMU 板级代码已经把 uart2 配成 IRQ 12，则 DTS 也要同步保持一致。

## 后续计划

### 阶段 1：整理当前 FreeRTOS 基础输出

- 修正 `task1/task2` 的 `0x0x` 输出问题。
- 调整 `debug_log_init()` 调用顺序，先初始化 uart2，再打印 `Hello FreeRTOS!`。
- 确认 `trusted_domain/build/`、`.o`、`.d`、`.lst` 等产物不会提交到仓库。

### 阶段 2：完善 OpenSBI trusted-domain 权限

在 DTS 中给 trusted-domain 增加 PLIC MMIO region：

```dts
tplic: tplic {
    compatible = "opensbi,domain,memregion";
    base = <0x0 0x0c000000>;
    order = <22>;
    mmio;
};
```

并加入：

```dts
regions = <&tmem 0x38>, <&tuart 0x18>, <&tplic 0x18>;
```

### 阶段 3：接入 PLIC

新增或完善：

```text
trusted_domain/driver/plic.c
trusted_domain/driver/plic.h
```

实现：

- `plic_init_hart7()`
- `plic_enable_irq_hart7(irq)`
- `plic_claim_hart7()`
- `plic_complete_hart7(irq)`

然后在 `handle_interrupt()` 中处理 S-mode external interrupt。

### 阶段 4：验证 uart2 中断

在 polling 输出稳定后，再启用 uart2 RX/TX 中断。

验证目标：

- uart2 输入中断能进入 FreeRTOS。
- 中断只落到 hart7。
- xv6 不会收到 uart2 的中断。
- FreeRTOS 和 xv6 不抢同一个 PLIC source。

### 阶段 5：考虑 xv6 和 FreeRTOS 通信

可选方向：

- 共享内存 ring buffer。
- PLIC 软件门铃或 IPI 通知。
- 简化版 virtio-mmio。
- OpenSBI vendor ecall 中转。

当前建议先不做通信，先把 hart7 FreeRTOS + PLIC 外部中断路径跑稳。
