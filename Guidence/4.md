# xv6 迁移到 OpenSBI Domain 的实施方案

当前状态：

- QuardAMP 已经能启动 OpenSBI。
- OpenSBI domain 已经划分成功。
- `hart0-hart6` 计划运行 `untrusted-domain`。
- `hart7` 已经可以运行 `trusted-domain` 裸机程序，并通过 `uart2` 输出。
- xv6 源码位置：`/home/yzl/Desktop/xv6-riscv`。

接下来建议先迁移 xv6，再迁移 RTOS。原因是 xv6 是 S-mode OS，天然适合放在 OpenSBI 后面；RTOS 往往默认跑 M-mode，后续需要单独处理 timer、中断和特权级适配。

## 总体目标

最终启动链路：

```text
pflash fw.bin
  -> lowlevelboot
  -> OpenSBI @ 0x80000000
  -> untrusted-domain: hart0-hart6 -> xv6 @ 0x82000000, S-mode
  -> trusted-domain:   hart7       -> trusted_fw / RTOS @ 0xb0000000, U/S-mode
```

第一阶段只要求 xv6 在 `hart0` 单核启动并打印；第二阶段再通过 SBI HSM 启动 `hart1-hart6`；最后再迁移 RTOS 到 `hart7`。

## 地址规划

当前固件布局建议保持如下：

```text
pflash 地址       fw.bin 偏移     目标内存地址       内容
0x20000000        0 KiB           0x20000000          lowlevelboot 原地执行
0x20080000        512 KiB         0x82200000          OpenSBI / xv6 使用的 DTB
0x20200000        2048 KiB        0x80000000          OpenSBI fw_jump.bin
0x20400000        4096 KiB        0xb0000000          trusted_fw.bin
0x20800000        8192 KiB        0x82000000          xv6 kernel.bin
```

xv6 先使用 2 MiB 装载窗口：

```text
0x82000000 - 0x821fffff  xv6 kernel
0x82200000               DTB
```

当前 xv6 `kernel/kernel` ELF 约 279 KiB，2 MiB 暂时足够。后续如果 kernel 超过 2 MiB，要么扩大窗口并移动 DTB，要么把 DTB 放到更高地址，例如 `0x8f000000`。

## 阶段 1：先把 xv6 改成 OpenSBI S-mode 启动

标准 xv6-riscv 是给 `qemu -machine virt -bios none -kernel kernel` 用的，入口默认在 M-mode。现在 OpenSBI domain 跳到 xv6 时已经是 S-mode，所以必须删掉或绕开 M-mode 初始化代码。

### 1.1 修改链接地址

文件：

```text
/home/yzl/Desktop/xv6-riscv/kernel/kernel.ld
/home/yzl/Desktop/xv6-riscv/kernel/memlayout.h
```

把 `kernel.ld` 里的入口地址从：

```ld
. = 0x80000000;
```

改成：

```ld
. = 0x82000000;
```

把 `memlayout.h` 里的：

```c
#define KERNBASE 0x80000000L
#define PHYSTOP (KERNBASE + 128*1024*1024)
```

改成：

```c
#define KERNBASE 0x82000000L
#define PHYSTOP (KERNBASE + 128*1024*1024)
```

这样 xv6 的链接地址、物理映射起点、OpenSBI domain 的 `next-addr` 保持一致。

### 1.2 修改 entry.S，不能再读 mhartid

当前 `entry.S` 里有：

```asm
csrr a1, mhartid
```

这个在 S-mode 下会触发非法指令。OpenSBI 跳到下一阶段时会传：

```text
a0 = hartid
a1 = next-arg1，也就是 DTB 地址
```

所以入口应该使用 `a0` 作为 hartid。

建议把 `entry.S` 的栈选择逻辑改成：

```asm
.section .text
.global _entry
_entry:
        # OpenSBI enters S-mode with:
        #   a0 = hartid
        #   a1 = fdt address
        mv tp, a0

        la sp, stack0
        li t0, 4096
        addi t1, a0, 1
        mul t0, t0, t1
        add sp, sp, t0

        call start
spin:
        j spin
```

这样 `cpuid()` 继续通过 `tp` 获取 hartid，不需要读 M-mode CSR。

### 1.3 修改 start.c，删掉 M-mode CSR 配置

当前 `start.c` 做了这些 M-mode 操作：

```c
w_mstatus(...)
w_mepc(...)
w_medeleg(...)
w_mideleg(...)
w_pmpaddr0(...)
w_pmpcfg0(...)
w_mie(...)
w_menvcfg(...)
w_mcounteren(...)
r_mhartid()
mret
```

这些在 OpenSBI 后面的 S-mode xv6 中都不应该执行。

第一阶段建议把 `start()` 简化成：

```c
void
start()
{
  w_satp(0);
  w_sie(r_sie() | SIE_SEIE | SIE_STIE);
  main();
}
```

其中：

- PMP 由 OpenSBI domain 管。
- 异常委托由 OpenSBI 管。
- hartid 已经在 `entry.S` 中写进 `tp`。
- timer 后续通过 SBI `set_timer` 做，不在 M-mode 写 `mtimecmp`。

### 1.4 增加 SBI 调用封装

新增：

```text
/home/yzl/Desktop/xv6-riscv/kernel/sbi.c
/home/yzl/Desktop/xv6-riscv/kernel/sbi.h
```

最小接口：

```c
// sbi.h
#pragma once
#include "types.h"

void sbi_set_timer(uint64 stime_value);
int sbi_hart_start(uint64 hartid, uint64 start_addr, uint64 opaque);
```

```c
// sbi.c
#include "types.h"
#include "sbi.h"

struct sbiret {
  long error;
  long value;
};

static inline struct sbiret
sbi_ecall(long ext, long fid, uint64 arg0, uint64 arg1, uint64 arg2,
          uint64 arg3, uint64 arg4, uint64 arg5)
{
  register uint64 a0 asm("a0") = arg0;
  register uint64 a1 asm("a1") = arg1;
  register uint64 a2 asm("a2") = arg2;
  register uint64 a3 asm("a3") = arg3;
  register uint64 a4 asm("a4") = arg4;
  register uint64 a5 asm("a5") = arg5;
  register uint64 a6 asm("a6") = fid;
  register uint64 a7 asm("a7") = ext;

  asm volatile("ecall"
               : "+r"(a0), "+r"(a1)
               : "r"(a2), "r"(a3), "r"(a4), "r"(a5), "r"(a6), "r"(a7)
               : "memory");

  return (struct sbiret){ .error = a0, .value = a1 };
}

void
sbi_set_timer(uint64 stime_value)
{
  sbi_ecall(0x54494d45, 0, stime_value, 0, 0, 0, 0, 0);
}

int
sbi_hart_start(uint64 hartid, uint64 start_addr, uint64 opaque)
{
  struct sbiret ret = sbi_ecall(0x48534d, 0, hartid, start_addr, opaque, 0, 0, 0);
  return ret.error;
}
```

然后把 `sbi.o` 加入 `Makefile` 的 `OBJS`。

### 1.5 timer 改为 SBI set_timer

当前 `trap.c` 中：

```c
w_stimecmp(r_time() + 1000000);
```

建议改成：

```c
sbi_set_timer(r_time() + 1000000);
```

并在 `start()` 或 `trapinithart()` 后初始化第一次 timer：

```c
sbi_set_timer(r_time() + 1000000);
```

这样 xv6 不依赖 S-mode 直接写 `stimecmp`，而是让 OpenSBI 负责 timer。

## 阶段 2：先做 xv6 单核最小启动

第一阶段不要急着上多核，也不要急着跑完整文件系统。先让 hart0 打印出来。

### 2.1 临时限制启动 hart

OpenSBI 目前会把 `hart0-hart6` 分给 untrusted-domain，但只会自动启动这个 domain 的 boot hart，也就是 `hart0`。

所以第一阶段可以不实现 HSM，先只验证：

```text
OpenSBI -> untrusted-domain -> hart0 -> xv6 main()
```

### 2.2 注意 virtio 问题

当前 Quard-Star DTS 中：

```text
uart0 @ 0x10000000
uart1 @ 0x10001000
uart2 @ 0x10002000
```

而标准 xv6 认为：

```c
#define VIRTIO0 0x10001000
```

这会和 `uart1` 地址冲突。如果 Quard-Star 机器目前没有挂 virtio-mmio disk，那么 xv6 执行：

```c
virtio_disk_init();
```

很可能会 panic。

因此第一阶段建议先做 console-only bring-up：

```c
consoleinit();
printfinit();
printf("xv6 on QuardAMP domain\n");
kinit();
kvminit();
kvminithart();
trapinit();
trapinithart();
plicinit();
plicinithart();
```

可以暂时跳过：

```c
binit();
iinit();
fileinit();
virtio_disk_init();
userinit();
scheduler();
```

等确认 S-mode 启动、页表、trap、timer 都正常后，再处理 virtio 或 ramdisk。

## 阶段 3：接入 QuardAMP build.sh

### 3.1 编译 xv6

在 `build.sh` 中 OpenSBI 和 trusted_domain 编译之后，增加 xv6 编译步骤：

```sh
# 编译 xv6
if [ ! -d "$SHELL_FOLDER/output/xv6" ]; then
mkdir $SHELL_FOLDER/output/xv6
fi

cd /home/yzl/Desktop/xv6-riscv
make clean
make TOOLPREFIX=$CROSS_PREFIX-
$CROSS_PREFIX-objcopy -O binary -S kernel/kernel $SHELL_FOLDER/output/xv6/kernel.bin
$CROSS_PREFIX-objdump --source --demangle --disassemble --reloc --wide kernel/kernel > $SHELL_FOLDER/output/xv6/kernel.lst
```

增加大小检查，避免覆盖 `0x82200000` 的 DTB：

```sh
XV6_SIZE=$(stat -c%s "$SHELL_FOLDER/output/xv6/kernel.bin")
if [ "$XV6_SIZE" -gt $((2 * 1024 * 1024)) ]; then
  echo "xv6 kernel.bin too large: $XV6_SIZE bytes, max is 2 MiB"
  exit 1
fi
```

### 3.2 合并进 fw.bin

在 `fw.bin` 合成阶段增加：

```sh
dd of=fw.bin bs=1k conv=notrunc seek=8K if=$SHELL_FOLDER/output/xv6/kernel.bin
```

对应关系：

```text
seek=8K -> 8192 KiB -> pflash 0x20800000
```

### 3.3 lowlevelboot 拷贝 xv6 到 DDR

在 `lowlevelboot/startup.s` 中增加：

```asm
//load xv6 kernel.bin
//[0x20800000:0x20a00000] --> [0x82000000:0x82200000]
    li      a0, 0x208
    slli    a0, a0, 20      // a0 = 0x20800000
    li      a1, 0x820
    slli    a1, a1, 20      // a1 = 0x82000000
    li      a2, 0x822
    slli    a2, a2, 20      // a2 = 0x82200000
    load_data a0,a1,a2
```

这段必须保证不覆盖 DTB。因为结束地址是 `0x82200000`，而 DTB 正好放在 `0x82200000`，所以 2 MiB 内不会踩到 DTB。

### 3.4 DTS 保持 untrusted-domain 入口

确认 `dts/quard_star_sbi.dts` 中：

```dts
udomain: untrusted-domain {
    compatible = "opensbi,domain,instance";
    possible-harts = <&cpu0 &cpu1 &cpu2 &cpu3 &cpu4 &cpu5 &cpu6>;
    regions = <&tmem 0x0>, <&tuart 0x0>, <&allmem 0x38>;
    boot-hart = <&cpu0>;
    next-arg1 = <0x0 0x82200000>;
    next-addr = <0x0 0x82000000>;
    next-mode = <0x1>;
    system-reset-allowed;
};
```

`next-mode = <0x1>` 表示 S-mode，符合 xv6。

## 阶段 4：启动验证

建议先不用 `run.sh` 的 `vc`，直接抓日志：

```sh
rm -f /tmp/trusted_uart2.log

timeout 8s output/qemu/bin/qemu-system-riscv64 \
  -M quard-star \
  -m 1G \
  -smp 8 \
  -drive if=pflash,bus=0,unit=0,format=raw,file=output/fw/fw.bin \
  -serial mon:stdio \
  -serial null \
  -serial file:/tmp/trusted_uart2.log \
  -monitor none \
  -parallel none \
  -nographic
```

预期 OpenSBI 输出：

```text
Domain1 Name                : trusted-domain
Domain1 HARTs               : 0x7*
Domain1 Next Address        : 0x00000000b0000000

Domain2 Name                : untrusted-domain
Domain2 HARTs               : 0x0*,0x1*,0x2*,0x3*,0x4*,0x5*,0x6*
Domain2 Next Address        : 0x0000000082000000
Domain2 Next Mode           : S-mode
```

预期 xv6 输出：

```text

```

```sh

```

```text
Hello Quard Star board!
```

如果 OpenSBI 输出正常但 xv6 没输出，优先检查：

```text
1. xv6 是否真的链接到 0x82000000
2. lowlevelboot 是否真的拷贝 kernel.bin 到 0x82000000
3. entry.S 是否仍然读取 mhartid
4. start.c 是否仍然执行 M-mode CSR
5. xv6 是否 panic 在 virtio_disk_init()
```

## 阶段 5：恢复 xv6 完整功能

### 5.1 处理块设备

标准 xv6 需要 virtio disk 才能跑 shell 和用户程序。当前 Quard-Star DTS 没有标准 virtio-mmio 节点，而且 `0x10001000` 已经是 `uart1`。

可选方案：

```text
方案 A：给 Quard-Star QEMU 增加 virtio-mmio 设备
  - 在 QEMU machine 中挂 virtio-mmio
  - 在 DTS 中添加 virtio 节点
  - 修改 xv6 memlayout.h 的 VIRTIO0 地址和 IRQ
  - 恢复 virtio_disk_init()

方案 B：先做内存 ramdisk
  - 把 fs.img 打包进内存
  - xv6 块设备层改为访问 ramdisk
  - 避免早期改 QEMU 设备模型

方案 C：先只跑内核级测试
  - 暂时不进入 userinit/scheduler
  - 先验证 timer、trap、PMP 隔离
```

建议顺序是 C -> A。先让内核稳定，再接真实 virtio。

### 5.2 timer 稳定性

timer 使用 SBI 后，需要确认：

```text
1. SIE_STIE 已打开
2. sstatus.SIE 在合适时机打开
3. 每次 clockintr() 都重新 sbi_set_timer()
4. OpenSBI 日志里有 time 扩展
```

OpenSBI 当前已经显示：

```text
Standard SBI Extensions : time,...,hsm,...
```

说明 timer 和 HSM 扩展都存在。

## 阶段 6：迁移 xv6 多核

单核 xv6 稳定后，再启用 `hart1-hart6`。

### 6.1 使用 SBI HSM 启动 secondary harts

OpenSBI 不会自动把 untrusted-domain 的所有 hart 都跳进 xv6。它只启动 domain 的 `boot-hart`。因此 xv6 要主动调用 SBI HSM：

```c
extern void _entry(void);

static void
start_secondary_harts()
{
  for(int hart = 1; hart <= 6; hart++){
    int err = sbi_hart_start(hart, (uint64)_entry, 0);
    if(err)
      printf("sbi_hart_start(%d) failed: %d\n", hart, err);
  }
}
```

注意不要启动 `hart7`，它属于 trusted-domain。

### 6.2 main.c 启动顺序建议

boot hart：

```text
consoleinit
printfinit
kinit
kvminit
kvminithart
procinit
trapinit
trapinithart
plicinit
plicinithart
timerinit
started = 1
sbi_hart_start(1..6)
scheduler
```

secondary hart：

```text
entry.S 设置 tp 和栈
main()
等待 started
kvminithart
trapinithart
plicinithart
timerinit
scheduler
```

### 6.3 NCPU 设置

可以保留：

```c
#define NCPU 8
```

因为 xv6 的 `cpus[]` 通过 hartid 直接索引，hart6 仍需要 index 6。只是启动时不要启动 hart7。

## 阶段 7：做 domain 隔离验证

xv6 跑起来后，在 xv6 kernel 中加临时测试：

```c
volatile uint64 *p = (uint64*)0xb0000000;
printf("try read trusted memory\n");
uint64 x = *p;
printf("unexpected read success: %lx\n", x);
```

预期：

```text
untrusted-domain 访问 0xb0000000 触发 load access fault
```

再测试 uart2：

```c
volatile char *uart2 = (char*)0x10002000;
*uart2 = 'X';
```

预期：

```text
untrusted-domain 不能写 uart2
```

如果 xv6 trap handler 能打印：

```text
scause
sepc
stval
```

就可以记录为 PMP 隔离验证结果。

## 阶段 8：再迁移 RTOS

xv6 稳定后再迁移 RTOS 到 trusted-domain。

RTOS 迁移前要先确认：

```text
1. RTOS 当前是 M-mode port 还是 S-mode/U-mode port
2. 是否直接访问 mstatus/mie/mtimecmp/mtime
3. 是否需要 PLIC/CLINT/MMIO 权限
4. 是否需要自己的中断入口
5. 是否需要 SBI timer
```

如果 RTOS 是 M-mode FreeRTOS port，不能直接放到普通 OpenSBI domain 里跑。可选路线：

```text
方案 A：把 RTOS 改成 S-mode port，通过 SBI 使用 timer
方案 B：trusted-domain 暂时继续跑裸机 trusted service
方案 C：更深地改 OpenSBI/platform，让某个 hart 保持特殊 M-mode runtime
```

建议先选 A 或 B，避免破坏当前 domain 框架。
